# mvu

当前设计基线：`v0.5-mvu-alpha`。当前阶段只做 **视觉方案 + 交互规则**；正式装配、实机回归和最终打包留给后续施工，不在本轮继续抢工。

本项目 MVU 坚持轻量化，只负责四件事：

1. 展示鲁迪因果值。
2. 展示世界纠正度。
3. 展示/收藏“鲁迪的一百种死亡方式”（仅短名，不展开死亡描写）。
4. 提供“一键复活鲁迪”。

## 唯一事实源
MVU只读每回合 `<causality>...</causality>` 中的因果、纠正、生死与RT状态；不得保存因果/纠正副本，也不得重新计算正文伦理或时间线账目。

## 当前视觉方向
主题升级为：`黑曜石法典 × 六面世界魔法纹 × 帝皇金印`。

- 黑曜石与古金为主体。
- 因果：暗绯裂痕。
- 世界纠正：冷蓝世界线。
- 两条进度都显示为20格，每格=5点。
- 顶部轻标签：帝皇监察 / 账目去重 / 旧世回流。
- 底部：百死图鉴 + 一键复活。
- 复活文案：`起来，账还没清。`

完整视觉：`003_视觉美化方案_v0.1.md`。
静态预览：`mvu_mockup_v0.2-beauty.html`。

## 死亡签机制
自帝皇T+3监察激活后：

- 因果值每首次向上跨过一个5点阈值，生成1张死亡签。
- 世界纠正每首次向上跨过一个5点阈值，也生成1张死亡签。
- 因果触发代表“债务收账”；纠正触发代表“主角光环/叙事兜底被拆掉后，正常世界风险重新生效”。
- 同一阈值只触发一次；数值下降后重新升回，不重复刷。
- 随机开局时，帝皇激活前已经跨过的历史因果阈值只作为基线，不追溯死亡。
- 单回合最多实际死亡一次；一次跨多个阈值则生成多个死亡签并进入等待队列。
- 死亡签优先从100个尚未发现、且符合当前场景的死法中抽取；无合理死法则等待后续场景。
- 死亡与复活本身都不改变因果和世界纠正。

完整规则：`002_死亡签触发机制_v0.1.md`。

## 百死图鉴
- 固定100个短名：`death-catalog.v0.1.json`。
- 100种是随机池，不要求一周目收满。
- 仅靠两条0~100数值的首次5点阈值，理论最大40张阈值死亡签；实际还会因随机开局基线而更少。
- 原作固定曲线从第一卷起，大致会产生约14张因果签 + 5张纠正签；正文实时变化可继续增加。
- 已发现词条高亮；未发现词条暗色；最新词条金边。

## 一键复活
- 鲁迪存活时禁用。
- 鲁迪死亡时可点。
- 复活只恢复生存状态，不清空因果、世界纠正、关系、KSET/CSET、OLD01、死亡图鉴、已跨阈值记录或等待死亡签。
- 若队列还有死亡签，至少等待一个新的有效剧情回合后才能再次结算，禁止同楼复活即再死。

## 允许的派生机械态
仅允许死亡机制自身使用：
- `death_seen`
- `death_marks_karma`
- `death_marks_correction`
- `death_queue`
- `last_death`
- `revive_count`
- `revive_pending`

## 禁止事项
- MVU接管主线剧情导演。
- 再造第二套复杂数据库。
- 死亡本身当作还债/纠正。
- 复活清空既有债务或关系。
- 当前设计阶段继续做正式装配、打包或实机施工。
