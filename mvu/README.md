# mvu

当前设计基线：`v0.5-mvu-alpha`。当前阶段只做 **视觉方案 + 交互规则**；正式装配、实机回归和最终打包留给后续施工，不在本轮继续抢工。

本项目 MVU 坚持轻量化，只负责四件事：

1. 展示鲁迪因果值。
2. 展示世界纠正度。
3. 展示/收藏“鲁迪的一百种死亡方式”（仅短名，不展开死亡描写）。
4. 提供“一键复活鲁迪”。

## 唯一事实源
MVU只读每回合 `<causality>...</causality>` 中的因果、纠正、生死与RT状态；不得保存因果/纠正副本，也不得重新计算正文伦理或时间线账目。

## 当前视觉方向
主题：`黑曜石法典 × 六面世界魔法纹 × 帝皇金印`。

- 黑曜石与古金为主体。
- 因果：暗绯裂痕。
- 世界纠正：冷蓝世界线。
- 两条进度都显示为20格，每格=5点。
- 顶部轻标签：帝皇监察 / 账目去重 / 旧世回流。
- 底部：百死图鉴 + 一键复活。
- 复活文案：`起来，账还没清。`

完整视觉：`003_视觉美化方案_v0.1.md`。
静态预览：`mvu_mockup_v0.2-beauty.html`。

## 死亡抽取机制 · 当前唯一口径
自帝皇T+3监察激活后：

- 因果值每首次向上跨过新的5点阈值，可触发本回合死亡抽取资格。
- 世界纠正每首次向上跨过新的5点阈值，也可触发本回合死亡抽取资格。
- **同一回合无论跨过几个新阈值，最多只随机抽取1种死亡方式。**
- 多余阈值仍登记为已跨过，但不排队、不补抽、不在后续回合追回。
- 同一阈值只触发一次；数值下降后重新升回，不重复刷。
- 随机开局时，帝皇激活前已经跨过的历史因果阈值只作为基线，不追溯死亡。
- 因果触发代表“债务收账”；纠正触发代表“主角光环/叙事兜底被拆掉后，正常世界风险重新生效”。
- 死亡与复活本身都不改变因果和世界纠正。
- 若当前场景没有合理死法，只允许保留1个 `pending_death_trigger`；pending存在时不再累积新的死亡抽取。

完整规则：`002_死亡签触发机制_v0.2.md`。

## 百死图鉴 · 八类
当前机器词表：`death-catalog.v0.2.json`。
人类可读索引：`004_百死图鉴八类整理_v0.1.md`。

八类：

- `✦ 魔法`：17
- `⚔ 战斗`：20
- `⌖ 旅行`：20
- `⌂ 日常`：8
- `♜ 权谋`：11
- `♛ 帝皇`：9（帝皇直接介入 + 六面世界超规格存在）
- `∞ 因果`：6
- `☠ 荒诞`：9

每个词条都带一个主分类和若干 `scene_tags`。随机时先按当前场景过滤，再在合理且优先未发现的候选中抽取。

100种是随机池，不要求一周目收满。两条0~100数值各有20个五点阈值，但由于**同回合多阈值合并成一次抽取**，实际死亡次数只会小于或等于阈值总数，不再固定等于“跨过多少格”。

## 一键复活
- 鲁迪存活时禁用。
- 鲁迪死亡时可点。
- 复活只恢复生存状态，不清空因果、世界纠正、关系、KSET/CSET、OLD01、死亡图鉴或已跨阈值记录。
- 同一回合复活后不得再次触发第二次死亡抽取。

## 允许的派生机械态
仅允许死亡机制自身使用：
- `death_seen`
- `death_marks_karma`
- `death_marks_correction`
- `pending_death_trigger`（最多1个）
- `last_death`
- `revive_count`
- `revive_pending`
- `last_death_draw_turn`

明确禁止：`death_queue`。

## 禁止事项
- MVU接管主线剧情导演。
- 再造第二套复杂数据库。
- 死亡本身当作还债/纠正。
- 复活清空既有债务或关系。
- 同一回合因为跨多个5点阈值连续抽取多个死法。
- 当前设计阶段继续做正式装配、打包或实机施工。
