# mvu

当前设计基线：`v0.5-mvu-alpha`。当前阶段只做 **视觉方案 + 交互规则**；正式装配、实机回归和最终打包留给后续施工。

本项目 MVU 坚持轻量化，只负责四件事：

1. 展示鲁迪因果值。
2. 展示世界纠正度。
3. 展示/收藏“鲁迪的一百种死亡方式”。
4. 提供“一键复活鲁迪”。

## 唯一事实源
MVU只读每回合 `<causality>...</causality>` 中的因果、纠正、生死与RT状态；不得保存因果/纠正副本，也不得重新计算正文伦理或时间线账目。

## 首次载入开机宣言 · 当前唯一口径
不再采用“第一楼自动播放视频”。

正式设计改为：

- 这张卡在当前设备/客户端 **第一次真正载入时**，播放一次用户选定的 MP4 开机宣言。
- 用户当前选定参考：`BV1a26FBpEsD`；音轨核心为用户所述“人类联邦宣言”。
- 视频作为第一次启动因果法典的 **开机宣告**，不是普通 Opening。
- 播放/跳过后写入本地 UI 偏好 `opening_ever_seen=true`。
- 以后新开聊天、回第一楼、刷新页面、切换时间线、重开 SillyTavern 都不得再次自动播放。
- 后续只保留一个很小的 `◉ 回听宣言` 入口，必须由用户主动点击。
- 回听从0秒有声播放，播完自动收回，不影响正文和任何状态。
- 不因普通卡版本更新自动重置“已看过”。只有未来更换全新宣言资源时，才允许通过版本化 manifest key 再触发一次。

### 声音优先级
首次载入优先尝试 **有声自动播放**。

若 Android WebView / 浏览器因缺少用户手势阻止有声 autoplay：
- 不允许静音播完后直接算“已看过”；
- 保留海报/首帧；
- 中央显示 `播放宣言`；
- 用户点击后从0秒有声播放。

该音轨本身就是开机仪式的重要组成，所以“有声优先、受平台限制时一键开始”高于“为了自动成功而静音播完”。

详细规则：`006_首次载入开机宣言与回听机制_v0.2.md`。
旧的 `006_首楼开屏动画与帝皇箴言轮换_v0.1.md` 仅作历史草稿，不再有效。

### 宣言与帝皇箴言的分工
- **人类联邦宣言**：第一次启动时的强烈文明/意志宣告。
- **帝皇箴言**：后续关于责任、选择、边界、宽恕与因果的温和校准。

不得把视频中的强烈排外/战争语气直接覆盖帝皇娘已经锁定的人格核心；她不是“见异族就杀”的单线处刑角色。

## 死亡抽取机制 · 当前唯一口径
自帝皇T+3监察激活后：

- 因果值每首次向上跨过新的5点阈值，可触发本回合死亡抽取资格。
- 世界纠正每首次向上跨过新的5点阈值，也可触发本回合死亡抽取资格。
- **同一回合无论跨过几个新阈值，最多只随机抽取1种死亡方式。**
- 多余阈值仍登记为已跨过，但不排队、不补抽、不在后续回合追回。
- 同一阈值只触发一次；数值下降后重新升回，不重复刷。
- 随机开局时，帝皇激活前已经跨过的历史因果阈值只作为基线，不追溯死亡。
- 因果触发代表“债务收账”；纠正触发代表“主角光环/叙事兜底被拆掉后，正常世界风险重新生效”。
- 死亡与复活本身都不改变因果和世界纠正。
- 若当前场景没有合理死法，只允许保留1个 `pending_death_trigger`；pending存在时不再累积新的死亡抽取。

完整规则：`002_死亡签触发机制_v0.2.md`。

## 一键复活
- 鲁迪存活时禁用。
- 鲁迪死亡时可点。
- 复活只恢复生存状态，不清空因果、世界纠正、关系、KSET/CSET、OLD01、死亡图鉴或已跨阈值记录。
- 同一回合复活后不得再次触发第二次死亡抽取。

死亡态主文案：`♻ 起来，账还没清。`

## 禁止事项
- MVU接管主线剧情导演。
- 再造第二套复杂数据库。
- 死亡本身当作还债/纠正。
- 复活清空既有债务或关系。
- 同一回合因为跨多个5点阈值连续抽取多个死法。
- 每个新聊天/第一楼自动重播开机宣言。
- 当前设计阶段继续做正式装配、打包或实机施工。
