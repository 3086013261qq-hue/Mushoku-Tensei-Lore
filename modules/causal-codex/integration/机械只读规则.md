# MVU 技术接入片段（不是世界书业务正文）

仅供最终本地装配侧合入已有变量更新说明。不自动新增、替换或改写任何 character_book 条目。

- `_causal_codex` 全部是模型可见只读机械态；不要对其任何子路径输出 JSONPatch，也不要修改 `$` 前缀字段。
- 继续采用已有唯一 `<UpdateVariable><Analysis>…</Analysis><JSONPatch>…</JSONPatch></UpdateVariable>` 格式。模块本身没有模型可写的伦理数值，不另开第二份输出协议。宿主有其他可写变量时照旧输出它们；本模块无更新时不为它虚构补丁。
- 每轮仍只输出 runtime v0.2 的唯一 `<causality>`。因果、纠正与 RT 账目由既有规则继承，UI 不重算。
- 若 `_causal_codex._pending_death_trigger` 有已锁定 name，保持同一死法，只有当前或后续合理场景中由正文真正确认死亡，才在生死行写死亡与该名称。尚未发生时不能仅因有签就写死亡。
- 若 `_causal_codex._revive_pending` 非 null，执行 `_mechanical_notice`：机械复活已生效，下一次有效输出应继承 `💀鲁迪生死: 存活｜死法: 无`。保留因果、纠正、RT、关系、历史与场景后果。
- 变量列表沿用全栈单数标签与宿主已有宏，使模型能读取只读投影：

```text
<status_current_variable>
{{format_message_variable::stat_data}}
</status_current_variable>
```

不要重复插入已有的变量列表。initvar 使用本包根字段片段，禁用条目让 MVU 读取；不得包一层 stat_data。
