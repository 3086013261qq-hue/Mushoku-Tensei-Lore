# 14. 死亡正文与脚本桥边界

死亡签只决定“死法类别/名称”，不能用 UI 文案替代正文事实。

抽签后：
- UI可显示已锁定死法；
- 若当前场景可合理发生，由后续正文自然结算；
- 若暂不可合理发生，状态保持 pending；
- 正文真正确认鲁迪死亡后，`<causality>` 生死行才写 `死亡`。

不得：
- 因为抽签就立刻在无关场景把鲁迪强行杀死；
- 鲁迪不在场时随便离屏荒诞死亡；
- 死亡后清空因果/纠正。

# 15. 一键复活

死亡时按钮：

`♻ 起来，账还没清。`

这是 MVU 的真实机械动作，允许脚本桥恢复生存状态；它不是普通剧情选择按钮，所以不要求一定走文本框再发送。

复活只改变：
- 鲁迪生存状态；
- 复活计数/机械标记。

绝不改变：
- 因果；
- 世界纠正；
- KSET/CSET；
- OLD01；
- 人物关系；
- 已发现死法；
- 已跨阈值。

同一回合复活后不再触发第二次死亡抽取。

下一次模型有效输出应继承为：

`💀鲁迪生死: 存活｜死法: 无`
