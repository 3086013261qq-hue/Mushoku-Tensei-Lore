## 2. 正确施工必须先创建派生工作副本

正式施工第一步必须是：

`授权母卡只读读取 → 创建独立派生工作副本 → 仅在派生副本上施工`

推荐工程语义：

- `source/original/`：永久只读证据层；
- `source/working/`：派生施工源；
- `build/candidate1/` 或等价构建目录：Candidate1 输出；
- 最终 Candidate JSON/PNG：独立新文件名，不覆盖原卡。

派生副本创建完成后，后续所有修改只允许发生在派生副本，包括：

- working v0.4 双实时层；

- 帝皇 T+3 Overlay；
- 帝皇娘与十二原体娘条目；
- MVU / ZOD / initvar / 机械状态；
- 宣言音频远程引用；
- 帝皇娘 WebP CDN；
- 死亡签 / 百死图鉴 / 一键复活；
- Candidate JSON / PNG。

## 3. 原条目“保留”不等于原文件“修改”

允许在**派生副本中的对应条目**进行已经封板的增量 patch，例如：

- 给派生副本内46条时间线加入 `RUNTIME_BASELINE` 与已审核机器标签；

这类行为属于：

`修改派生卡`

不是：

`修改授权母卡原件`

必须严格区分。
